عددی که random می‌دهد اصلاً تصادفی نیست!

۱۴۰۵/۰۸/۲۷تپه‌نوردیامنیت

یه بار داشتم کد یه سایت رو می‌خوندم. دیدم کد تأیید پیامکی رو با random.randint می‌سازه. اولش به نظرم عادی بود.

ولی بعد یه چیزی یادم افتاد که خیلی‌ها نمی‌دونن. عددی که random می‌ده واقعاً تصادفی نیست. این عدد از یه فرمول ریاضی میاد. اگه چند تا از این عددها رو ببینی، می‌تونی عددهای بعدی رو دقیق حساب کنی. یعنی می‌شه کد تأییدِ نفر بعدی رو از قبل دونست.

تو این پست نشون می‌دم این اتفاق چطور می‌افته، تو کدوم زبان‌ها هست و به جاش چی باید نوشت. یه آزمایشگاه هم ساختم که خودت تو مرورگر امتحانش کنی.

اول یه مولد خیلی ساده

کامپیوتر برای ساختن عدد تصادفی معمولاً از یه «مولد شبه‌تصادفی» استفاده می‌کنه. «شبه» یعنی عددها فقط تصادفی به نظر می‌رسن. ساده‌ترین مولد این شکلیه: یه عدد تو حافظه‌ش داره و هر بار با یه فرمول عوضش می‌کنه. به این مدل مولد می‌گن LCG.

[1]:
state = (state * 1103515245 + 12345) % 2147483648
# عدد جدید هم خروجی است و هم حافظهٔ دور بعد

همین. یه ضرب، یه جمع و یه باقی‌مونده. این عددِ جدید دو تا کار می‌کنه: هم خروجیِ همین مرحله‌ست، هم نقطهٔ شروعِ مرحلهٔ بعد.

حالا فرض کن کسی یکی از این خروجی‌ها رو ببینه. اون سه تا عدد ثابتِ فرمول راز نیستن، چون تو کدِ خودِ زبان نوشته شدن. پس با یه ضرب و یه جمع، خروجی بعدی رو حساب می‌کنه. یعنی خروجی، حافظهٔ مولد رو لو می‌ده.

مولدهای واقعی پیچیده‌ترن، ولی ایده همینه: یه حافظهٔ داخلی که با یه فرمولِ ثابت عوض می‌شه. سؤال اصلی همیشه اینه: می‌شه از روی خروجی‌ها اون حافظه رو دوباره ساخت؟ تقریباً همیشه جوابش مثبته.

معروف‌ترین مولد: Mersenne Twister

خیلی از زبان‌ها از مولدی به اسم Mersenne Twister استفاده می‌کنن. ماژول random تو Python، تابع mt_rand تو PHP و تابع rand تو Ruby همه همین مولدن.

حافظهٔ این مولد بزرگه: ۶۲۴ عدد. فکر کن یه دفترچه با ۶۲۴ خونه داره. هر بار که ازش عدد می‌خوای، یکی از خونه‌ها رو برمی‌داره، یه کم به‌هم می‌ریزه و بهت می‌ده. وقتی همهٔ خونه‌ها مصرف شد، از روی همون‌ها یه دفترچهٔ جدید می‌سازه.

مشکل اینجاست که این به‌هم‌ریختن برگشت‌پذیره. از روی هر خروجی می‌شه عددِ داخلِ همون خونه رو دقیق درآورد. پس اگه ۶۲۴ خروجیِ پشت سر هم ببینی، کل دفترچه رو داری. از اون به بعد یه کپیِ دقیق از مولدِ سرور دستته.

این کد همین کار رو می‌کنه. تابع untemper همون به‌هم‌ریختن رو برعکس می‌کنه:

[2]:
import random

# به‌هم‌ریختن را برعکس می‌کند
def untemper(y):
    y ^= y >> 18
    y ^= (y << 15) & 0xefc60000
    t = y
    for _ in range(5): t = y ^ ((t << 7) & 0x9d2c5680)
    y = t
    t = y
    for _ in range(3): t = y ^ (t >> 11)
    return t & 0xffffffff

# سرور؛ مهاجم از داخلش خبر ندارد
server = random.Random()

# مهاجم این ۶۲۴ عدد را دیده
seen = [server.getrandbits(32) for _ in range(624)]

# کپیِ مولد سرور ساخته می‌شود
state = tuple([untemper(v) for v in seen] + [624])
attacker = random.Random()
attacker.setstate((3, state, None))

print(server.getrandbits(32) == attacker.getrandbits(32))

True

جواب True یعنی عدد بعدیِ سرور و عدد بعدیِ کپی دقیقاً یکی‌ان.

یه نکته: عدد ۶۲۴ برای وقتیه که مهاجم عددِ کامل رو ببینه. کد تأییدِ شش‌رقمی فقط بخشی از هر عدد رو نشون می‌ده. اونجا مهاجم نمونهٔ بیشتری لازم داره، حدود هزار تا، و حسابش هم سخت‌تره. ولی باز هم شدنیه. پس کد تأییدی که با randint ساخته بشه امن نیست.

یه چیز دیگه هم این مشکل رو جدی‌تر می‌کنه. معمولاً کل برنامه از یه مولدِ مشترک استفاده می‌کنه. اگه یه جای بی‌خطرِ سایت، مثلاً یه بازی ساده، عددهای این مولد رو نشون بده، مهاجم همون‌ها رو جمع می‌کنه. بعد کد تأیید یا شناسهٔ کاربرِ بعدی رو هم حساب می‌کنه. یعنی ضعفِ یه بخشِ بی‌اهمیت به یه بخشِ حساس می‌رسه.

↙ همین حمله رو خودت امتحان کنتو آزمایشگاه نمونه جمع کن، دکمهٔ پیش‌بینی رو بزن و ببین درست درمیاد یا نه. همه‌چیز تو مرورگر خودت اجرا می‌شه.

سه اشتباه رایج با عدد شروع

هر مولد کارش رو با یه عدد شروع می‌کنه. اینجا بهش می‌گیم «عدد شروع»؛ تو کد اسمش seed هست. خیلی‌ها فکر می‌کنن با دستکاریِ این عدد، مولد امن می‌شه. این سه حالت رو زیاد دیدم.

۱. عدد شروعِ ثابت. مثلاً همیشه ۴۲. اینجا مولد هر بار دقیقاً همون عددها رو می‌سازه. یعنی کد تأییدِ همهٔ کاربرها یکی می‌شه!

۲. عدد شروع از روی ساعت. ظاهرش فکر خوبیه، چون ساعت مدام عوض می‌شه. ولی مهاجم خودش درخواست رو فرستاده و می‌دونه تقریباً چه ساعتی بوده. پس چند هزار عددِ دور و برِ اون ساعت رو امتحان می‌کنه. هر کدوم که کدِ خودش رو ساخت، همون عدد شروعِ سروره. حالا کدِ نفر بعدی رو هم می‌دونه.

محدودیتِ «۵ بار تلاش» هم کمکی نمی‌کنه. مهاجم دیگه بین ۹۰۰ هزار کد حدس نمی‌زنه. فقط دو سه حالت براش مونده.

[4]:
import time
now = int(time.time())

# سرور با ساعت شروع می‌کند و کدِ مهاجم را می‌سازد
random.seed(now)
my_code = random.randint(100000, 999999)

# مهاجم فقط می‌داند درخواستش چند ثانیه پیش بوده
for s in range(now - 5, now + 1):
    r = random.Random(s)
    if r.randint(100000, 999999) == my_code:
        # عدد شروع پیدا شد؛ عدد بعدی کدِ نفر بعدی است
        print(r.randint(100000, 999999))
        break

۳. عدد شروع از یه مولد ضعیف. بعضی‌ها برای اینکه کار «تصادفی‌تر» بشه، خودِ عدد شروع رو هم با randint می‌سازن. ولی این عدد هم از همون مولدِ قابل‌پیش‌بینی میاد و چیزی رو بهتر نمی‌کنه. قاعده ساده‌ست: اگه عدد شروع قابل حدس باشه، کل مولد قابل حدسه.

پس دستکاریِ عدد شروع راه‌حل نیست. راهِ درست اینه که برای عددهای حساس اصلاً از این مولدها استفاده نکنی.

بقیهٔ زبان‌ها

این مشکل مخصوصِ Python نیست. تقریباً هر زبانی دو جور مولد داره. یکی سریعه و برای بازی و شبیه‌سازی ساخته شده. اون یکی امنه و برای رمز و کد تأیید. اشتباه همیشه یکیه: برنامه‌نویس اولی رو جای دومی به کار می‌بره.

برای هر زبان یه خط گذاشتم که نباید بنویسی (✗) و یه خط که باید بنویسی (✓).

JavaScript

تابع Math.random تو مرورگر Chrome و تو Node از مولدی به اسم xorshift128+ استفاده می‌کنه. حافظه‌ش فقط ۱۲۸ بیته و فرمولش خیلی ساده‌ست. اون‌قدر ساده که با حل یه دستگاه معادله، از روی فقط ۴ خروجی کل حافظه‌ش پیدا می‌شه. تو آزمایشگاه همین کار رو کردم.

[5]:
// ✗
const otp = Math.floor(Math.random() * 900000) + 100000;

// ✓ Node
const otp2 = crypto.randomInt(100000, 1000000);

// ✓ browser
function randomCode() {
  const buf = new Uint32Array(1);
  const limit = 4294967296 - (4294967296 % 900000);
  // عددهای بالای این حد دور ریخته می‌شوند تا همهٔ کدها هم‌احتمال باشند
  do crypto.getRandomValues(buf); while (buf[0] >= limit);
  return 100000 + (buf[0] % 900000);
}

Java

تو Java، کلاس java.util.Random فقط ۴۸ بیت حافظه داره. هر بار که nextInt() صدا زده می‌شه، ۳۲ بیت از همین حافظه مستقیم بیرون میاد. پس فقط ۱۶ بیت مخفی می‌مونه، یعنی حدود ۶۵ هزار حالت. این‌ها تو کسری از ثانیه امتحان می‌شن. با دو خروجی کل حافظه پیدا می‌شه.

// ✓

PHP و WordPress

تابع mt_rand تو PHP همون Mersenne Twister هست. از نسخهٔ ۷٫۱ به بعد، تابع rand هم همین مولد رو داره.

اینجا یه راه میان‌بر هم هست. عدد شروعِ این مولد فقط حدود ۴ میلیارد حالت داره. ابزاری به اسم php_mt_seed همهٔ این حالت‌ها رو تو چند دقیقه امتحان می‌کنه. با یکی دو خروجی، عدد شروعِ درست پیدا می‌شه و بقیهٔ عددها معلوم می‌شن.

خبر خوب اینکه WordPress این مشکل رو حل کرده. تابع wp_rand از نسخهٔ ۴٫۴ (سال ۲۰۱۵) امنه و تابع wp_generate_password هم روی همین ساخته شده. نسخه‌های خیلی قدیمی، حدود سال ۲۰۰۸، لینک بازیابی رمز رو با mt_rand می‌ساختن و همین باعث یه حملهٔ معروف شد. خطرِ امروز بیشتر تو افزونه‌هاییه که خودشون مستقیم mt_rand یا rand رو صدا می‌زنن.

[7]:
// ✗
$otp = mt_rand(100000, 999999);
$otp = rand(100000, 999999);

// ✓ PHP 7+
$otp = random_int(100000, 999999);

// ✓ WordPress 4.4+
$otp  = wp_rand(100000, 999999);
$pass = wp_generate_password(20, false);

C# و Go و C و Ruby

این چهار زبان هم همین وضع رو دارن. فقط دو نکته:

  • تو C#، اگه new Random() رو بدون عدد شروع بسازی، نسخه‌های جدید مولد بهتری بهت می‌دن. ولی اگه عدد شروع بدی، مثل new Random(42)، همون مولد قدیمی برمی‌گرده که با ۵۵ خروجی کپی می‌شه.
  • تو Go، تابع‌های math/rand از نسخهٔ ۱٫۲۰ خودشون عدد شروعِ تصادفی می‌گیرن و از نسخهٔ ۱٫۲۲ مولد بهتری دارن. ولی با rand.NewSource(seed) همون مولد قدیمی برمی‌گرده که با ۶۰۷ خروجی کپی می‌شه.

مستنداتِ هر دو زبان هنوز می‌گن این مولدها برای کار امنیتی ساخته نشدن.

قانون طلایی

فقط همین یه جمله یادت بمونه: اگه نباید کسی بتونه یه عدد رو حدس بزنه، اون عدد نباید از مولدِ معمولی بیاد.

کد تأیید، توکنِ ورود، کد تخفیف، رمز موقت و هر شناسه‌ای که نباید حدس زده بشه، همه باید از مولدِ امن بیان. مولدِ معمولی برای بازی و انیمیشن و شبیه‌سازی عالیه. فقط برای رمز و کد تأیید سراغش نرو.
